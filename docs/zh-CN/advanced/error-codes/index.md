# 错误码参考

本文汇总 Kinal 编译器与语言服务器共享的内置诊断码，按类别整理，并为各预注册模板说明触发条件与修复方法。例子区分可复现失败和需要上下文的触发形态。

---

## 编号格式

- `E-` 表示错误，会阻止编译继续通过。
- `W-` 表示警告，默认不阻止编译，但可以配合 `--Werror` 升级为错误。
- 中间三字母表示诊断大类，例如 `SYN` 表示语法、`SEM` 表示语义、`RES` 表示名称解析。
- 末尾五位数字标识已注册模板；动态分配诊断的稳定性边界见下文。

## 使用方式

```bash
kinal build main.kn --lang zh
kinal build main.kn --lang zh --Werror
```

## 编写说明

- 示例优先展示最常见、最容易读懂的触发方式，而不是追求覆盖编译器内部的所有变体。
- 如果多个错误码只是在作用域或实体种类上不同，文档会沿用同一种最小代码形态，重点突出触发条件和修复策略。
- 语法类错误示例通常是局部片段；语义类错误示例更偏向完整声明或完整函数。

## 目录覆盖与代码稳定性

本目录对应 C 编译器 kn_diag_registry.c 中预注册的诊断模板。未预注册的新诊断会按出现顺序分配组内编号，因此可能还会看到 GEN／WRN 等目录外诊断；其自动编号不应视为跨版本稳定 API。定位问题时同时保留阶段、标题、详情、文件位置和编译器版本。

示例是局部片段；导入、外围类型或函数上下文按所属规则补全，不能把刻意错误的片段当成可运行程序。使用 --emit check 可定位前端问题；后端和链接器失败可能没有相同格式的语言诊断码。应优先修复第一个根因，再检查后续连带错误。

编译器 --lang zh 与编辑器 diagnosticsLanguage 分别选择诊断语言；自定义 --locale-file 覆盖模板文本，不改变语言语义。不要仅按翻译后的提示文本匹配诊断。

使用完整 Native 构建检查入口诊断；--emit check 不要求可执行入口。变量未使用和不可达代码是级别 2 警告，可加 --warn-level 2。顶部 Return／Throw 等非法结构可能先触发 E-SYN-00106；解析恢复、重载筛选和模板归一化均可能使实际编号不同。
