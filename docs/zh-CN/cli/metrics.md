# 项目复杂度（自举编译器）

`kinal metrics` 复用项目源文件选择、语法树和语义分析，直接显示复杂度或导出
JSON、HTML。仅自举编译器支持；不会生成程序、调用链接器或运行项目。

```sh
kinal metrics --project ./kinal.knproj
kinal metrics --project . --all
kinal metrics --project . -o reports/metrics.json
kinal metrics --project . -o reports/metrics.html
kinal metrics Main.kn --no-module-discovery --format json
kinal metrics --project . --max-cyclomatic 20 --max-cognitive 25 --max-nesting 5
```

省略参数时使用当前目录的 `kinal.knproj`。`--format text|json|html` 指定格式；
省略时根据 `-o` 扩展名选择，默认文本。省略 `-o` 或指定 `-o -` 输出到 stdout，
诊断和 `--time` 的耗时留在 stderr。JSON/HTML 保留全部记录；`--top N` 仅限制
终端热点榜，默认 10，`--all` 或 `--top 0` 显示全部函数体。

HTML 无外部依赖，支持离线查看、筛选、排序和函数详情。

## 统计内容

| 层级 | 指标 |
| --- | --- |
| 项目 | 行数、token、声明、语句数、复杂度合计/最大值/P95、递归组、语义分析覆盖情况 |
| 文件 | Unit、导入、物理/代码/注释/空行、类型与函数数、复杂度 |
| 类型 | 字段、方法、方法复杂度权重、类继承深度、直接派生类、接口、已解析类型耦合 |
| 函数 | 圈复杂度、认知复杂度、嵌套、参数/局部变量、返回/抛出、循环/分支/捕获、跳转/Record、Unsafe、Await、显式分配语法、闭包捕获、调用关系、扇入/扇出、Halstead、可维护性参考值 |

默认统计当前 profile 实际参与编译的项目源文件。`ReachableUnits` 不包含不相关
文件；需要覆盖完整 SourceSet 时选择 `AllSources` profile。`--include-dependencies`
加入实际参与分析的包/运行库。支持 `--profile`、`--target`、`--pkg-root`、
`--stdpkg-root` 和标准诊断选项。

泛型按源码定义统计一次；多个实例的语义依赖取并集。匿名函数、局部函数和
Block 字面量单独列出，内部判断不会再次计入父函数。全局变量和字段初始化器
单列结构指标；其词法指标和可维护性暂不可用。无函数体声明 CC 为 0、MI 为 null。

## 如何理解数值

- **结构圈复杂度 CC**：每个函数体基数 1；每个 If/ElseIf、条件表达式、循环、
  非 default Case、Catch、`&&`/`||` 加 1。统计源码中的语法判断，包括常量条件。
  Jump/Record 单列；有非结构化跳转时，这不是完整控制流图的数学秩，也不是
  所有执行路径的数量。
- **认知复杂度 `kinal-cognitive-v1`**：控制结构加 1 和当前嵌套深度；ElseIf、
  Else 加 1，不额外收取嵌套罚分；Switch 整体计一次；逻辑运算符序列切换、
  Jump、直接调用递归组成员各加 1。Try、花括号、Case、Return、Break、Continue
  本身不加分。嵌套函数从深度 0 开始。借鉴 Sonar 的模型，但不冒充跨语言一致值。
- **Halstead**：按 Kinal token 分类操作符/操作数，计算词汇量、长度、体积、
  难度和工作量。标识符/字面量按 token 种类和拼写去重，花括号/圆括号/逗号/
  分号不计。插值字符串词法上仍是一个操作数，内部表达式另参与结构分析。词法范围采用解析器声明区间：顶层包含修饰符，
  成员从 Function/Constructor 或属性访问器关键字开始。
- **可维护性 MI**：0–100，越高表示该启发式下越容易维护。公式为
  `(171 - 5.2*ln(max(V,1)) - 0.23*CC - 16.2*ln(max(代码行,1)))*100/171`，
  限制范围并四舍五入，不加注释奖励。词法/行数口径与 Visual Studio 不同，
  不应直接比较绝对值，也不能把它当正确性或总体质量评分。
- **耦合与调用图**：依据已绑定的实际类型/调用目标，忽略原始类型与自身类型。
  扇入是范围内不同调用者数；扇出包含已知的外部与内建目标。虚调用只展示声明
  目标，动态调用不猜测；递归组只用范围内的直接调用边，是保守下界。
  未实例化泛型、动态分发的语义信息可能不完整，报告明确提供 `bound`、
  `bound_source_calls` 等覆盖信息。属性元数据依赖不计入耦合。

行数满足 `物理行 = 代码行 + 纯注释行 + 空行`；代码与注释共同行同时出现在
代码行和注释行中。末尾换行不会多产生一个空行，字符串中的注释标记不会误计。
JSON 内嵌每项指标的完整定义，schema 为 `kinal.metrics.v1`。热点应结合最大值、
P95 和具体函数判断；项目总 CC 随规模增长，本身不能用于评价架构好坏。
HTML 默认标注 CC > 10、认知复杂度 > 15 或嵌套 > 4，标注不会自动让命令失败。

当前不声称预测运行性能、实际分配次数、缺陷概率或测试覆盖率，也没有重复代码、
完整死代码和非结构化控制流分析。[完整口径与公式](../../cli/metrics.md)。

## CI 上限与错误

`--max-cyclomatic N`、`--max-cognitive N`、`--max-nesting N` 可选，N 为非负整数。
任一函数体超过（不是等于）上限时，仍导出报告并列出违规位置，返回 3。

| 返回码 | 含义 |
| --- | --- |
| 0 | 成功，配置的上限通过 |
| 1 | 项目/语法/语义或输出 I/O 错误 |
| 2 | 参数错误 |
| 3 | 成功分析，但超过配置的上限 |

分析失败不会覆盖已有报告，输出位置不能是源码、项目清单或包文件。普通构建
不执行复杂度分析。该功能没有向原版 C 编译器增加命令。
